FAQ

Frequently Asked Questions

Common questions about AI agent governance, the ecosystem, and how to get started.

What is AI agent governance and why does it matter?

AI agent governance is the practice of enforcing safety policies, access controls, and behavioral boundaries on autonomous AI agents in production. As AI agents gain more autonomy—executing code, making API calls, managing infrastructure—they need the same governance that operating systems provide to processes: capability isolation, resource limits, and audit trails. Without governance, a single misbehaving agent can cascade failures across an entire system. Agent OS provides this governance layer with 0% policy violations, compared to 26.67% with prompt-based approaches.

How do Execution Rings work in Agent Hypervisor?

Execution Rings in Agent Hypervisor mirror CPU ring architecture. Ring 0 is the highest privilege (hypervisor config, requires SRE Witness attestation). Ring 1 handles non-reversible actions requiring trust score above 0.95. Ring 2 covers standard reversible actions for agents with trust above 0.60. Ring 3 is a read-only sandbox for unknown agents. Agents can request dynamic ring elevation (like sudo) with a time-bounded TTL, and are automatically demoted if their trust score drops. Child agents spawned by a parent inherit the parent's ring level minus one, preventing privilege escalation.

What is the difference between Agent OS and prompt-based guardrails?

Prompt-based guardrails ask the LLM to self-police, which fails 26.67% of the time. Agent OS takes a fundamentally different approach: it enforces governance at the system level using deterministic policy engines, capability sandboxing, and POSIX-inspired access controls. Think of it like the difference between asking a user to “please don’t delete system files” versus enforcing file permissions at the OS kernel level. Agent OS controls what agents can do (capability-based), not just what they should not do (filter-based).

How do I get started with the Agent Governance Ecosystem?

Start with Agent OS: pip install agent-os-kernel. Define your governance policies in Python or YAML, create a sandboxed environment, and run your AI agent within it. For multi-agent systems, add AgentMesh (pip install agentmesh-platform) for trust scoring and identity. For production reliability, add Agent SRE (pip install agent-sre) for SLOs and chaos testing. For advanced session governance, add Agent Hypervisor (pip install agent-hypervisor) for execution rings and saga orchestration. All four tools work together seamlessly.

What frameworks does the Agent Governance Ecosystem integrate with?

The ecosystem is integrated with 20+ major AI frameworks. Merged contributions include Dify (65K stars), LlamaIndex (47K stars), GitHub Copilot ecosystem (21.6K stars), and Microsoft Agent-Lightning (15K stars). Active integrations span OpenAI Agents, Anthropic, Google A2A, Oracle Agent Spec, AutoGen, CrewAI, Haystack, PydanticAI, HolmesGPT, and more. PyPI packages like langgraph-trust and openai-agents-trust provide drop-in governance for specific frameworks.

How does SRE apply to AI agents?

Site Reliability Engineering (SRE) for AI agents means treating agent systems with the same rigor as production services. Agent SRE provides: SLOs for response time, accuracy, cost per inference, and safety compliance; error budget tracking with burn rate alerts; chaos engineering to inject failures and test agent resilience; canary deploys with automated rollback; replay debugging for failure analysis; and cost guardrails to prevent runaway inference spending. It integrates with OpenTelemetry and Prometheus for full observability.
